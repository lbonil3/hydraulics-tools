# Summary Sheet layout tools (maintainers only)

The app does not need anything in this folder at run time. It uses `../summary-layout.js`, which these scripts generated.

## What the layout is

The two official TxDOT SWP3 Summary Sheet PDFs (`swp3b23.pdf` 1 acre or more, `swp3a23.pdf` less than 1 acre, "July 2023" template) are **flat** PDFs: no AcroForm fields, and the printed text is outlined vector art (the text layer is empty). So the app draws entries on top of the original pages at measured positions.

`summary-layout.js` holds, per variant and per field id, the page and position in PDF points (top-left origin, y down, 1224 x 792 pages): check boxes (x, y, w, h), text lines (x0, x1, baseline y), multi-line paragraph lines, table column and row rules, and title-block cells.

## How it was made

1. Table rules, underline rules and check-box glyph rectangles were read from the PDF vector drawings with PyMuPDF.
2. The pages were rendered at 3x and OCR'd (RapidOCR) only to find which label sits on which row.
3. `build_layout.py` combines the two, snaps every check box to a real glyph rectangle, and fails loudly (`LAYOUT ASSERT`) if a field cannot be placed. Both variants report 0 unsnapped fields.
4. `overlay.py` draws every field box over a page render so a person can check the result by eye.

Limits of this folder: the intermediate JSON inputs (`ocr.json`, `geo.json`, `ul.json`) came from an exploratory session and are not regenerated by a script here, and the official PDFs are not in this repo (see below). `build_layout.py` is kept as the record of how the committed layout was derived, not as a one-command rebuild.

## Checking the layout

`node swp3-builder/test-summary.js` checks that every printed field in the catalog has a layout entry, that no layout entry is orphaned, that every box lies inside the page, and (if you have the PDFs) fills both sheets and reads the text back with `pdftotext`. Set `SWP3_PDF_DIR` to a folder holding the two PDFs.

## The PDFs are not in this repository

TxDOT's CAD disclaimer says the standards files "are copyrighted by the Texas Department of Transportation and may not be resold", the sheet footer says "All Rights Reserved", and no redistribution grant was found. The app therefore asks the user to download the sheet from TxDOT once and choose the file. It checks the file's SHA-256 against the expected value and keeps the bytes in the browser (IndexedDB) for offline use.

Expected SHA-256:

- `swp3b23.pdf` b973a8e3bcd002ed5dc8598c3b146f7e1ee63ae45d091f545c94eeb8ddeaaa25
- `swp3a23.pdf` 70d4fa738f7105423b035f04276f0061896b19c914dffab5cc3716eed2cfc205

Source: https://ftp.txdot.gov/pub/txdot-info/cmd/cserve/standard/roadway/ (listed on the Roadway Standards page, https://www.dot.state.tx.us/insdtdot/orgchart/cmd/cserve/standard/rdwylse.htm). That host sends no CORS headers, so a web page cannot fetch it directly.

If TxDOT permission to redistribute is ever confirmed: put the two files in `swp3-builder/assets/`, set `BUNDLED = true` in `summary.js`, and add them to the service worker file list.

## When TxDOT revises the sheets

A new sheet will have a different hash and different positions. Re-measure, regenerate `summary-layout.js`, update the hashes in `summary.js` (`SHEETS`) and re-run the tests.
